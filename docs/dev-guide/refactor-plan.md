# 初始化执行器简化重构方案

本方案依据用户文档（初始化用户指南）重新界定范围，只保留初始化功能。它先梳理可执行的形式化规则，再给出把现有执行器收敛到该规则的简化路径。方案只到设计层，不依赖现有实现细节。

## 形式化规则

从用户文档提炼实体、命名函数与约束。

实体包括领域、固定的资产类型集合与可见性取值。

```text
D = ⟨short, english, chinese⟩                  领域，如 search / search-engineering
A = {platform, toolkit, example, context,
     journal, intention, …}                    资产类型，固定封闭集合
V ∈ {public, private}                          可见性，缺省 public
```

命名与挂载位置由领域与资产类型唯一确定，不引入额外参数。

```text
repo_domain(D) = quanttide-{D.short}

repo(a, D) = qtcloud-{D.short}                       若 a = platform
           = quanttide-{D.short}-toolkit              若 a = toolkit
           = quanttide-laboratory-of-{D.english}      若 a = example
           = quanttide-{a}-of-{D.english}              其余

mount(a)   = apps/qtcloud-{D.short}                  若 a = platform
           = packages/quanttide-{D.short}-toolkit     若 a = toolkit
           = examples/default                         若 a = example
           = {dir(a)}/{a}                             其余
```

初始化的含义是创建主仓库、创建选定资产仓库、再逐个挂载。

```text
init(cfg),  cfg = ⟨D, Asel ⊆ A, V, provider, workspace⟩:
    create repo_domain(D)
    ∀ a ∈ Asel.  create repo(a, D)
    ∀ a ∈ Asel.  mount repo(a, D) → repo_domain(D) @ mount(a)
```

约束是判定实现是否正确的依据。

1. 命名封闭：所创建仓库的每个名称都等于某个命名函数作用于 `D`，无自由命名；
2. 非空：作为子模块目标的仓库必须至少有一个提交，否则指针不可解析；
3. 可见性一致：同一次初始化创建的所有仓库取同一可见性 `V`；
4. 不越界：只创建主仓库与 `Asel` 内的资产仓库，不遍历组织；
5. 有确认：每个远程写操作之前存在一次确认；
6. 可恢复：任意中断后，重跑能前进或安全停机，外部效果至多一次；
7. 幂等：重复初始化收敛到同一结果，不产生重复仓库或重复挂载。

## 范围收敛

用户文档只需要初始化，而现有设计面向七种场景、十余种操作类型。可据此删减，得到如下对比。

| **维度** | **现有设计** | **简化后** |
| :-- | :-- | :-- |
| 场景 | 新建、补全、追加、挂载、聚合、更名、发布 | 仅初始化 |
| 操作类型 | 约十余种 | 创建仓库、写初始文件、挂载子模块、收尾 |
| 入口 | 计划、确认、执行、验证四个子命令 | 单个 `init` |
| 计划 | 持久化为不可变文件并单独审批 | 由配置确定性生成，即时确认 |
| 恢复 | 每种操作各写一套接续逻辑 | 由幂等效果统一保证 |
| 可见性 | 不支持 | 由配置决定 |

范围收敛有三条直接后果。其一，操作类型从十余种缩到四种，每种操作的语义可以集中成一份声明。其二，计划成为配置的纯函数，无需持久化与兼容键，也无需单独的审批文件。其三，恢复不再需要逐操作手写，只要每个效果幂等即可。

## 目标设计

目标是用一份声明描述四种操作，让执行、恢复与校验都从它派生。

### 单一入口

`init` 读取配置，先确定性生成操作清单并展示，确认后执行；机器调用可用 `--yes` 跳过交互。确认事件仍满足约束五。

### 操作描述符

每种操作声明其前置条件、纯目标、幂等效果、接续谓词与成功判据，成为唯一事实来源。

- 前置条件：该操作可执行的判定；
- 纯目标：由配置与环境算出的期望内容与引用，不触碰外部；
- 幂等效果：把目标落到环境，重放不产生额外效果；
- 接续谓词：中断后判断能否安全前进到该操作；
- 成功判据：判定该操作已正确完成，用于收尾校验。

仓库的写集由描述符派生，不再手工登记。

### 每仓库状态机

单个仓库在初始化中的状态很少，且严格单向。

- 未创建：目标仓库还不存在；
- 已创建：仓库存在且已有初始提交，对应约束二；
- 已挂载：在该仓库作为资产时，已挂入主仓库的对应目录；
- 已推送：本地提交已确认到达远端。

主仓库只经历未创建、已创建、已推送；资产仓库额外经历已挂载。

### 效果与恢复

创建对已存在且非空的仓库直接通过，否则带初始文件创建，保证约束二。挂载对被挂载过的目录比较现有引用，一致则跳过、不一致则刷新，保证约束七。收尾推送前先核对远端是否已含目标提交，保证约束六。重跑 `init` 时，上述效果各自幂等，整体收敛。

## 重构步骤

1. 冻结范围：配置只接受初始化，其余场景从入口移除或标记弃用。
2. 收敛入口：把计划、确认、执行、验证收敛为单个 `init`，内部保留先展示后确认。
3. 定义计划生成器：实现 `cfg → operations` 的纯函数，产出的操作清单可复现。
4. 收敛操作类型：只保留创建仓库、写初始文件、挂载子模块、收尾四种，并各自写出一份描述符。
5. 保证非空：创建一律带初始文件，落实约束二。
6. 接入可见性：配置增加 `visibility`，贯穿到创建参数。
7. 内部校验：`init` 结束时自动做一次结果核对，落实约束一、三、四。
8. 清理冗余：删除审批记录文件与兼容键白名单等只服务于旧多命令流程的部分。

## 验收标准

- 新增一种资产类型只需增加一行命名与挂载声明，执行、恢复、校验的代码不动；
- 单条 `init` 在本地与云端两种模式下都建成主仓库与六个资产仓库，并挂载到正确目录；
- 中断后重跑 `init` 收敛到同一结果，无重复仓库或重复挂载；
- 配置为私有时，创建出的仓库均为私有；
- 任一约束不满足时，`init` 在确认之前拒绝执行。
